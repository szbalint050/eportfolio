API Documentation

PortfolioPro  ·  v1.0  ·  June 2026  ·  Base URL: http://localhost:3001

1. General Conventions

All request bodies and response bodies use JSON. Set Content-Type: application/json on every request with a body. Protected endpoints require a JWT in the Authorization header:

Authorization: Bearer <token>

Tokens are issued by POST /auth/register and POST /auth/login and are valid for 7 days. Error responses always include a message field. CORS is configured for http://localhost:5173.

StatusMeaning
200Success
201Resource created
400Validation error — missing or invalid field
401No token / invalid token / wrong credentials
403Authenticated but not authorised (wrong owner, not admin)
404Resource not found or not owned by requesting user
409Conflict — duplicate email or duplicate skill name

POST /auth/register Public

Creates a new user account. Also creates a default portfolio and an empty profile. Returns a JWT immediately — no separate login step required.

GET /auth/me Auth Required

Returns the full profile of the currently authenticated user, resolved from the JWT's userId claim.

200 OK — returns Profile object 401 No / invalid token 404 User not found
POST /auth/logout Public

Stateless logout. Because JWTs are self-contained, the server takes no action. The client is responsible for discarding the token. This endpoint exists as a semantic convention and for future token blocklist integration.

4. Profile — /profile

All profile endpoints require authentication. Each user has exactly one profile, keyed by their user ID.

GET /profile Auth Required

Returns the authenticated user's profile.

200 OK — returns Profile object 401 404 Profile not found
PUT /profile Auth Required

Partially updates the authenticated user's profile. Only the fields listed below are accepted — unknown fields are silently ignored. Updating username also syncs the value in the users store.

Soft-deletes the account — sets is_active: false on the user record and removes the profile entry. The user cannot log in after this action.

6. Projects — /projects

All project endpoints require authentication. Projects are always scoped to the authenticated user's portfolios — cross-user access is blocked at the ownership check level.

7. Skills — /skills

GET /skills is the only public (unauthenticated) endpoint in the API.

GET /skills Public

Returns the full list of available skills. The backend seeds 12 skills on startup.

[{ "id": 1, "name": "JavaScript" }, { "id": 2, "name": "TypeScript" }, // ...]
200 OK
POST /skills Admin Only

Adds a new skill to the shared list. Requires the "admin" role. Skill names are compared case-insensitively to prevent duplicates. Body: name (required).

{ "id": 13, "name": "Rust" }
201 Created 400 Missing name 401 403 Not admin 409 Already exists
The skills list lives in memory only and resets on server restart. The client-side localStore.getSkills() provides 17 skills as a static array and does not call this endpoint.

8. Client-Side localStore API

frontend/src/lib/localStore.ts exports a singleton localStore object used by all React components for data access. It uses five localStorage keys: pp_users, pp_profiles, pp_projects, pp_session, pp_bookings.

User Methods

registerUser(username, email, password) → StoredUser | {"{ error: string }"}
Creates a new user after validating email uniqueness and password length (≥ 8). Calls createDefaultProfile() automatically. Returns the created user on success or {"{ error }"} on failure.
Errors: "An account with this email already exists." | "Password must be at least 8 characters."
loginUser(email, password) → StoredUser | {"{ error: string }"}
Finds user by email (case-insensitive) and verifies password via btoa encoding.
Error: "Invalid email or password."
findUserByEmail(email) → StoredUser | undefined
Case-insensitive email lookup.
findUserById(id) → StoredUser | undefined
UUID lookup — used by AuthContext to restore a session on page load.

Session Methods

setSession(userId) → void
Writes the user's UUID to localStorage["pp_session"]. Called after login or registration.
getSession() → string | null
Reads localStorage["pp_session"]. Returns null if no session exists. Called on app mount to restore auth state.
clearSession() → void
Removes localStorage["pp_session"]. Called on logout. Does not delete user or profile data.

Profile Methods

createDefaultProfile(user) → void
Creates a blank profile for a new user if one does not already exist. Idempotent — safe to call multiple times.
getProfile(userId) → StoredProfile | undefined
Returns the profile for the given user ID.
updateProfile(userId, data: Partial<StoredProfile>) → StoredProfile
Merges data into the existing profile and persists to localStorage["pp_profiles"]. Syncs username to the user record if changed. Throws Error("Profile not found") if the profile does not exist.

Project Methods

getProjects(userId) → StoredProject[]
Returns all projects for the given user. Returns an empty array if none exist.
addProject(userId, data) → StoredProject
Creates a new project with auto-generated UUID, likes: 0, views: 0, and ISO 8601 createdAt. data omits id, userId, likes, views, createdAt.
updateProject(userId, projectId, data) → StoredProject
Merges data into the project, preserving id and userId. Throws Error("Project not found") if not found or not owned.
deleteProject(userId, projectId) → void
Removes the project matching both projectId and userId. Silent no-op if not found.
getSkills() → string[]
Returns the static list of 17 skill name strings. No parameters, no localStorage read.
