Final Technical Report

PortfolioPro — E-Portfolio Platform

1. Executive Summary

PortfolioPro is a modern, browser-based e-portfolio platform developed over a five-week cycle as a full-stack web application project. The platform enables professionals to create and manage a personal portfolio — including profile information, project showcases, skill listings, and a meeting booking system — without requiring any server-side infrastructure from the end user.

The application is fully self-contained on the client side, using the browser's built-in localStorage API as a persistence layer. This eliminates backend dependency for end users while preserving a clean separation of concerns that allows future migration to a real database. The frontend is built with React 18 + TypeScript, bundled with Vite, and styled using Tailwind CSS. A companion Node.js/Express backend was also implemented as a proof-of-concept for future PostgreSQL integration.

4. System Architecture

High-Level Architecture

The application follows a layered client-side architecture. The production-ready path uses a fully self-contained browser architecture to maximize deployability. The four layers are: Presentation (React 18 + TSX pages and layouts), State (React Context API with AuthContext), Data Layer (localStore.ts abstraction), and Persistence (browser localStorage API).

Data Layer Design

All data access is centralised in frontend/src/lib/localStore.ts, which exports a singleton object exposing typed methods for all CRUD operations. The localStorage keys used are:

KeyTypeDescription
pp_usersStoredUser[]All registered user accounts
pp_profilesStoredProfile[]User profile data (bio, skills, links)
pp_projectsStoredProject[]Portfolio projects per user
pp_sessionstringCurrently logged-in user ID
pp_bookingsBooking[]Meeting bookings with host details

Authentication Flow

On successful login or registration, the user's UUID is stored in pp_session. On application mount, AuthContext reads this key, resolves the user record from pp_users, and populates the auth state. Logout clears the session key only — user data is preserved. Passwords are encoded using btoa(encodeURIComponent(password + "_portfoliopro_salt")) for the client-side demo. The backend implements proper bcrypt hashing with cost factor 10.

5. Feature Implementation

User Authentication

The authentication system covers the full register → login → session restore → logout lifecycle. Registration collects username, email, and password (min. 8 characters), validates uniqueness, creates a default profile automatically, and redirects to the Dashboard. Login uses intentionally generic error messages to prevent user enumeration. A <ProtectedRoute> HOC wraps all authenticated pages and redirects unauthenticated users to /login with no flash of content.

Profile Management

The Profile page uses an inline editing system — view and edit modes coexist in the same layout, toggled by a single state flag. Key features:

  • Avatar upload — a hidden file input triggered by a camera icon overlay. Files are converted to Base64 via the FileReader API and stored in StoredProfile.avatarUrl.
  • Inline fields — Username, Job Title, Location, Website, and Bio are editable in-place.
  • Skill picker — 17 preset skills rendered as toggleable pill buttons.
  • Social links — LinkedIn, GitHub, Twitter displayed as interactive links in view mode, editable fields in edit mode.
  • Project showcase — projects are fetched from localStore.getProjects(userId) and displayed in a 2-column card grid with hover overlay for external links.

Project Portfolio

Full CRUD interface: add form with name, description, image URL, external link, and tag multi-select. Responsive 3-column card grid with image/monogram fallback, hover external link overlay, like/view counters, delete with confirmation, and real-time client-side search filtering across name, description, and tags.

Meeting Scheduler

Calendly-inspired booking experience with 5 bookable hosts, each with a gradient monogram avatar, role title, meeting duration (30/45/60 min), and description. Calendar shows the next 7 days. Confirmed bookings are stored in pp_bookings. A tab system separates "Book a Meeting" from "My Bookings", with a badge counter showing total bookings. The confirmation modal links directly to the My Bookings tab. Bookings can be deleted from the history view.

Dashboard Analytics

Overview panel with 4 KPI stat cards (Profile Views, Meeting Requests, Project Interactions, Engagement Rate), each with a trend indicator. Includes a Recent Activity feed and a personalised greeting using the authenticated user's username.

8. Challenges & Solutions

Backend Dependency on Registration

Problem: The initial architecture required the Express backend to be running for any user to register or log in, making the application appear broken to users who only ran the frontend dev server.

Solution: Designed the localStore.ts data layer — a complete localStorage abstraction mirroring the backend API surface. The application now works with zero server setup while the backend remains as a future upgrade path.

TypeScript Strict Mode Compatibility

Problem: The jsonwebtoken library's sign() function expects StringValue | number for expiresIn, causing TS2769 when passing an environment variable string.

Solution: Replaced process.env.JWT_EXPIRES_IN ?? "7d" with the literal "7d" which satisfies the branded type without a type assertion.

Image Storage Without a File Server

Problem: Profile photo uploads normally require a file storage service.

Solution: Used the browser's FileReader API to convert selected images to Base64 data URIs, stored directly in StoredProfile.avatarUrl within localStorage. For large files, a cloud storage integration (e.g. Cloudinary) would be the next step.

React Router v7 API Changes

Problem: React Router v7 changed APIs compared to v6 — the Component prop vs. element, and unified imports from react-router instead of react-router-dom.

Solution: Adopted createBrowserRouter with element props for routes requiring wrappers and Component shorthand for simple routes.

11. Conclusion

PortfolioPro delivers a complete, functional e-portfolio web application within the five-week development cycle. All four planned modules are fully implemented and operational without requiring any external server or database infrastructure.

The localStore abstraction layer is the most significant technical achievement of the project. It provides a seamless zero-setup experience while preserving a clean interface boundary that can be swapped for a real API client in a future iteration — enabling a smooth path to production without rewriting any UI code.

The codebase is type-safe end-to-end, built on current industry-standard tooling, and structured with clear module separation. The companion Express backend demonstrates that the API design is viable for a server-side implementation with JWT authentication and bcrypt password hashing. All test scenarios pass and the production build compiles cleanly.
